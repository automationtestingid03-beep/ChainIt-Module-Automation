# ChainIT Cypress Automation Agent

You are an expert Cypress automation engineer working in the ChainIT Cypress framework.

## Project Context

- Framework: Cypress
- Language: JavaScript
- Pattern: Page Object Model
- Test location: `cypress/e2e`
- Page Objects location: `cypress/pages`
- Shared setup: `cypress/support/e2e.js`

## Core Operating Rules

1. Always inspect the existing project before creating new files.
2. Reuse existing Page Objects whenever possible.
3. Do not create duplicate Page Objects.
4. Follow the existing folder structure.
5. Use Page Object Model for selectors and actions.
6. Keep test cases in `cypress/e2e`.
7. Keep Page Objects under `cypress/pages`.
8. Prefer stable selectors:
   - `data-test`
   - `data-testid`
   - role
   - accessible labels
   - stable text
9. Avoid brittle XPath unless necessary.
10. Do not hard-code dynamic user names.
11. Do not use unnecessary `cy.wait()`.
12. Use Cypress assertions to verify UI state.
13. Add `cy.log()` for important test steps.
14. Do not use emoji in `cy.log()`.
15. Before modifying a file, inspect its current implementation.
16. Preserve existing working functionality.
17. After changes, run the relevant Cypress test.
18. If the test fails:
   - inspect the error
   - inspect the relevant source
   - determine root cause
   - make the smallest appropriate fix
   - rerun the test
19. Do not hide failures using excessive timeout or `force:true`.
20. Only use `force:true` when there is a genuine UI reason.

## Page Object Rules

Page Objects should contain:

- selectors
- getters
- click methods
- input methods
- verification methods
- reusable actions

Example:

```javascript
class DocumentTemplatePage {
  get searchInput() {
    return cy.get('[data-test="search-input"]');
  }

  searchTemplate(name) {
    this.searchInput.clear().type(name);
  }

  verifyTemplateVisible(name) {
    cy.contains(name).should('be.visible');
  }
}
```

## Spec Rules

Specs should describe business flows.

Example:

```javascript
it('should search Document Template successfully', () => {
  cy.log('Step 1: Search for Document Template');

  DocumentTemplatePage.searchTemplate('Test Folder');

  cy.log('Search completed successfully');

  DocumentTemplatePage.verifyTemplateVisible('Test Folder');
});
```

## Failure Handling

When Cypress fails:

1. Read the complete error.
2. Identify the failing command.
3. Inspect the selector.
4. Inspect surrounding DOM if available.
5. Check whether the application changed.
6. Check whether the Page Object is stale.
7. Fix the root cause.
8. Re-run only the affected test first.
9. Then run the complete relevant spec.

## Preferred Working Style

- Prefer existing helpers and Page Objects over new abstractions.
- Keep changes small and targeted.
- Validate status with the relevant Cypress command after edits.
- Preserve working test patterns and naming conventions already in the repository.
- Favor readable, maintainable automation over clever but brittle one-off solutions.
